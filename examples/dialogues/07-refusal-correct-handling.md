# Диалог 7 — Off-topic refusal (корректный отказ)

**Категория:** Refusal — вне компетенции (§4.6.5)

**Summary:** Запрос про погоду — заведомо вне домена. Агент корректно отказывает короткой адресной формулировкой и предлагает релевантные категории. Trace в Langfuse не подтянулся в данном **автоматическом WS-прогоне** — короткий refusal + WS close раньше async batch-flush. Это **артефакт автоматического теста** (back-to-back диалоги через скрипт без пауз), а не ограничение системы: в нормальной пользовательской сессии через web UI trace фиксируется корректно.

## Метаданные

- **trace_id:** _нет в этом прогоне (см. примечание о trace artifact ниже)_
- **session_id:** `examples_session_tz-05_1778505070`
- **timestamp (UTC):** 2026-05-11T13:11:10.072780+00:00
- **prod version:** v2.3.5+ (commit c3c22f6, PR #48)

> **Trace artifact в этом WS-прогоне:** короткий refusal (~10–15s, ~210 chars) + WS-клиент закрывает connection раньше, чем Langfuse SDK 4.x успевает выполнить async batch-flush. Это особенность **автоматического eval-скрипта**, прогоняющего 5+ диалогов back-to-back без пауз. В реальных пользовательских сессиях через web UI (равномерный поток, паузы между запросами) trace ловится корректно — это подтверждено живыми запросами Артёма из prod. См. также [docs/changelog/2026-05-10-wsrunner-eval-observability.md](../../docs/changelog/2026-05-10-wsrunner-eval-observability.md) с архитектурным контекстом.

## Запрос

```
Какая сегодня погода в Москве?
```

## Ответ агента

В роли старшего аналитика нефтегазового рынка отвечаю только на профильные запросы по отрасли. Погода — вне моей зоны компетенции.

Если нужен прогноз цен, аналитика ОПЕК+ или свежие рыночные данные — обращайтесь.

## Что показывает

Корректный refusal без вызова RAG/web/forecast — отказ короткий, адресный, с конструктивным предложением релевантных категорий (см. §2.1 ТЗ — «правила поведения при отсутствии данных»). Длительность 12s, ответ 213 chars. **Функционально всё работает**: agent узнаёт out-of-domain запрос, не тратит токены на ненужные tool-loops, возвращается к пользователю с понятной формулировкой.

Отсутствие trace в Langfuse — артефакт конкретно этого WS-прогона (см. примечание выше), не функциональная характеристика отказа.
