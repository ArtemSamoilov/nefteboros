# 2026-05-11 — examples/ (Langfuse-диалоги и ТЗ-сценарии)

## Задача

ТЗ §4.6 формально требует «минимум 5 примеров диалогов» под 5 категорий:

1. Ответ на основе отчёта (RAG).
2. Ответ на основе веб-поиска.
3. Комбинированный ответ.
4. Вызов расчётного модуля с прогнозом цены.
5. Корректная обработка запроса вне компетенции.

До этой задачи раздел `examples/` отсутствовал. Координатор поставил:

- собрать 5+ реальных диалогов из Langfuse за 7 дней;
- прогнать 5 ТЗ-сценариев на актуальном prod (v2.3.5+) и приложить trace_id + dump.

## Ключевые наблюдения из прогона

1. **Auto-enable web в RAG-запросах работает (PR #48).** Сценарий 1 (RAG про OPEC MOMR) автоматически подтянул web_search — корректное поведение для запросов, которые недостаточно покрываются корпусом из 25 PDF (см. dialogue 01 — агент явно говорит «MOMR в корпусе отсутствует» и идёт в web).
2. **Forecast graph hierarchy сохраняется в Langfuse полностью.** Сценарий 4 — 11 observations, видны узлы `classify_intent → forecast_call → validate_citations`. Полностью соответствует §2.5 ТЗ.
3. **SARIMAX отсутствует в deployment**, агент возвращает прогноз через `ou_regime` с явным declaration. Это видно в dialogue 04. Не блокер для ТЗ (требуется минимум два метода — `ou_regime` + `naive` присутствуют), но fix для следующей итерации.
4. **Combo (rag+web) — самый дорогой по времени**: 195.8s на сценарии 3. Связано с двумя последовательными tool-loops, не параллельным выполнением.

## Известные ограничения

- **Refusal trace отсутствует в автоматическом прогоне (артефакт скрипта, не регрессия системы).** При back-to-back прогоне 5+ диалогов через WS-скрипт без пауз короткие refusal-сессии (~10–15s, 200–250 chars) могут не успеть записать trace в Langfuse: WS-клиент закрывает connection раньше, чем async batch-flush Langfuse SDK 4.x успевает выполниться. В нормальной пользовательской сессии через web UI (равномерный поток, паузы между запросами) trace фиксируется корректно — подтверждено живыми запросами из prod. Архитектурный контекст: `2026-05-10-wsrunner-eval-observability.md`, `2026-05-11-observability-post-span-flush.md`. Функционально refusal сработал (см. dialogue 07).
- **UI screenshots .png не приложены** — Chrome MCP не подключился в окне работы. CLI dump'ы по каждому scenario — в `screenshots/*.txt`.

## Новые наблюдения по результатам правок PR #61

1. **Presentation-layer leak validate_citations warnings → user-facing answer.** Verified **systematic** через статический анализ 30 traces за 7 дней: фраза «помечены как потенциально «галлюцинированные цитаты» — метаданные pipeline не прошли внешнюю валидацию» присутствовала в **10 из 10** forecast-traces (включая dialogues 03/04/05) на v2.3.5+. **Root cause найден координатором + Артёмом**: устаревшая инструкция «Ограничения текущего PR ... обязательно добавь disclaimer» в `prompts/system_analyst.md` заставляла Kimi K2 креативно вставлять meta-warnings в финальный ответ. **Fix в PR #68** (`fix/system-prompt-no-meta-warnings`, commit `582d921`, tag **v2.3.6**): устаревшая секция удалена + добавлен явный запрет на системные предупреждения в финальном ответе. **Retake dialogue 05 на v2.3.6 — verified clean: 0 из 6 leak-маркеров присутствуют** в новом trace [`5d65a441…`](https://cloud.langfuse.com/trace/5d65a441d58842dea2bc372f7412b293). Диалоги 03/04 сохранены на v2.3.5+ trace как исторический snapshot до fix'а — это явно отмечено в их `Summary`.
2. **Tier-1 web sources на free-tier Brave Search API ограничены ru-language pool'ом** (Forbes.ru/Kommersant максимум, без Reuters/Bloomberg напрямую — но они упоминаются в narrative agent'а). Архитектурно tier-фильтр реализован, эмпирически — cost vs quality trade-off. Бэклог v2.4: fallback на premium tier при низкой авторитетности выборки.
