# 2026-05-11 — examples/ (Langfuse-диалоги и ТЗ-сценарии)

## Задача

ТЗ §4.6 формально требует «минимум 5 примеров диалогов» под 5 категорий:

1. Ответ на основе отчёта (RAG).
2. Ответ на основе веб-поиска.
3. Комбинированный ответ.
4. Вызов расчётного модуля с прогнозом цены.
5. Корректная обработка запроса вне компетенции.

До этой задачи раздел `examples/` отсутствовал. Координатор поставил:

- собрать 5+ реальных диалогов из Langfuse за 7 дней;
- прогнать 5 ТЗ-сценариев на актуальном prod (v2.3.5+) и приложить trace_id + dump.

## Ключевые наблюдения из прогона

1. **Auto-enable web в RAG-запросах работает (PR #48).** Сценарий 1 (RAG про OPEC MOMR) автоматически подтянул web_search — корректное поведение для запросов, которые недостаточно покрываются корпусом из 25 PDF (см. dialogue 01 — агент явно говорит «MOMR в корпусе отсутствует» и идёт в web).
2. **Forecast graph hierarchy сохраняется в Langfuse полностью.** Сценарий 4 — 11 observations, видны узлы `classify_intent → forecast_call → validate_citations`. Полностью соответствует §2.5 ТЗ.
3. **SARIMAX отсутствует в deployment**, агент возвращает прогноз через `ou_regime` с явным declaration. Это видно в dialogue 04. Не блокер для ТЗ (требуется минимум два метода — `ou_regime` + `naive` присутствуют), но fix для следующей итерации.
4. **Combo (rag+web) — самый дорогой по времени**: 195.8s на сценарии 3. Связано с двумя последовательными tool-loops, не параллельным выполнением.

## Известные ограничения

- **Refusal trace gap.** Короткие refusal-диалоги (~10–15s, 200–250 chars) теряются в Langfuse из-за async batch-flush. Уже частично закрыто `2026-05-10-wsrunner-eval-observability.md` (flush в handle_task wrapper) + `2026-05-11-observability-post-span-flush.md`, но крайне короткие WS-сессии всё ещё проскальзывают. Функционально refusal работает (см. dialogue 07: ответ агента вернулся корректно, потерян только trace).
- **UI screenshots .png не приложены** — Chrome MCP не подключился в окне работы. CLI dump'ы по каждому scenario — в `screenshots/*.txt`.
