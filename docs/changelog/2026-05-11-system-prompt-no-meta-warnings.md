# 2026-05-11 — system_analyst.md: убрать meta-warnings в финальном ответе

**PR:** `fix/system-prompt-no-meta-warnings`
**Связано:** [nefteboros/prompts/system_analyst.md](../../nefteboros/prompts/system_analyst.md), сессия C при работе над examples (PR #61, dialogue 05).

## Bug

В multi-tool forecast диалогах в **финальном ответе пользователю** появлялась строка:

> «**Системное предупреждение:** внутренние метаданные модели (`[ADR-0024]`, `[forecast_model:*]`) помечены как потенциально «галлюцинированные цитаты» — формальная внешняя валидация меток pipeline не подтверждена.»

Это leak internal state валидатора в user-facing message. Verified сессией C: **systematic в 10 из 10** multi-tool forecast traces за последние 7 дней.

## Root cause

В `system_analyst.md` была устаревшая секция «Ограничения текущего PR (явно для пользователя)»:

> «В этой версии графа RAG-корпус и web-search ещё не подключены. … В конце ответа **обязательно**: ‹Для production-аналитики этому ответу нужен overlay из RAG…›»

Эта инструкция написана для **раннего minimal-graph PR'а**, когда RAG/web ещё не были интегрированы. Сейчас RAG (ADR-0011/0016) и web-search (ADR-0022) **полностью подключены** к графу, а инструкция в system prompt всё ещё заставляет LLM добавлять disclaimer о неподключённых источниках.

Kimi K2 как «послушная» модель пытается выполнить устаревшую инструкцию + creative interprets — на multi-tool forecast (где в context видны citations типа `[Forecast: ou_regime, ...]` и `[forecast_model:...]`) генерит meta-комментарий «галлюцинированные цитаты … валидация pipeline не подтверждена», обходя прямой текст из устаревшей инструкции.

## Fix

- Удалена секция «Ограничения текущего PR» полностью (инструкция устарела).
- В секцию «Чего не делать» добавлены два явных правила:
  1. **Не выводи системные предупреждения / meta-комментарии о валидации citations, метаданных модели или процессе pipeline.** Citation tags (`[Forecast: ...]`, `[forecast_model:...]`, `[ADR-XXXX]`) — валидная разметка источников, а не объект саморефлексии.
  2. **Не комментируй внутреннюю структуру pipeline в финальном ответе.** Пользователь видит ответ аналитика, не инженерный лог.

## Тест

После merge + deploy: прогнать multi-tool forecast запрос на проде (например, «Спрогнозируй цену Brent на 6 месяцев с учётом санкций 2026»). Финальный assistant message **не должен** содержать строку «Системное предупреждение» / «галлюцинированные цитаты» / «валидация меток pipeline».

Если фикс работает — сессия C обновит trace в `examples/dialogues/05-multi-tool-sanctions-forecast.md` на новый prod-trace без leak'а.
