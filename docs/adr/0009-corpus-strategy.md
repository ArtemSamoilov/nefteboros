# ADR-0009 — Стратегия RAG-корпуса nefteboros

- **Дата:** 2026-05-05
- **Статус:** Принято
- **Контекст:** PR `feature/corpus-bootstrap`
- **Связано:** ADR-0001 (форк Ouroboros), будущий ADR-0010 (RAG-pipeline), будущий ADR-0011 (web-search в runtime)

## Контекст

ТЗ требует RAG-пайплайн с приоритизацией источников: **отчёты OPEC/МЭА/EIA → web-search как дополнение**. Целевая аудитория — топ-менеджмент Сбера (ассистент Г. Грефа), что меняет акценты:

- Сбер — крупнейший российский госбанк, кредитор Роснефти/Газпрома/Лукойла/Новатэка/Татнефти
- Нефтегаз = ~20% ВВП РФ, ~40% бюджета, ~60% экспорта
- Поэтому корпус не «глобальный энергоаналитик», а **«нефтегаз с фокусом на риск/стратегию для российского госбанка»**

Это второй приоритет после соблюдения формальных требований ТЗ.

## Решение

Корпус из **25 документов**, ~135 МБ, разбит на **4 блока** по типу контента и lifecycle:

| Блок | Тип контента | Lifecycle | Кол-во |
|---|---|---|---:|
| **1. Стратегии и видения** | Государственные/институциональные long-term документы | обновление 1-5 лет | 10 |
| **2. Корпоративка РФ** | Annual + IFRS/РСБУ крупнейших РФ-компаний | обновление 1 год | 7 |
| **3. Operational срез** | Свежие monthly/quarterly digest глобального рынка | обновление 1-3 мес | 5 |
| **4. Геополитика и санкции** | Тематические обзоры think tanks / CRS | обновление 6-12 мес | 3 |

Полный список — в `data/metadata/manifest.yml`.

Баланс языков: ~50/50 RU/EN — Артём попросил уйти от моего изначального 70/30 в пользу российской специфики.

## Аргументация

### Почему 4 блока

Каждый блок имеет **разный жизненный цикл** и **разную retrieval-стратегию**:

1. **Стратегии** — низкая частота обновлений, high-confidence для long-term вопросов («Когда пик нефти? Какие цели РФ к 2050?»). RAG-веса этих документов должны быть высокими, потому что *они* дают агенту stake-in-time и направление.
2. **Корпоративка** — обновляется ежегодно, источник для финансовых вопросов («Какова добыча Газпрома? Дивиденды Лукойла?»). RAG обращается к ним при упоминании конкретной компании.
3. **Operational срез** — самые свежие данные (последний MOMR/STEO/GMR). Используется для «что сейчас на рынке», но **глубокий архив не нужен** — для свежих новостей runtime web-search.
4. **Геополитика** — узкоспециализированные обзоры (price cap, Иран). Подключаются по тематическому intent.

Альтернатива «один большой корпус без блоков» — отвергнута: при retrieval похожие куски из MOMR-2025 и MOMR-2026 будут конкурировать, тогда как 1 актуальный MOMR + долгосрочные стратегии — естественная декомпозиция.

### Почему ровно эти 24 документа

Отбор шёл от **категорий вопросов пользователя** (taxonomy), а не от «какие документы вообще существуют»:

| Категория вопроса | Ключевые документы |
|---|---|
| РФ операционка («сколько добыли? куда экспорт?») | Газпром AR, Роснефть AR + IFRS, Лукойл AR, Новатэк AR, Татнефть AR |
| РФ госфинансы («реалистична ли цена в бюджете?») | Минэк СЭР 2026-2028, Энергостратегия РФ-2050 |
| Санкции и геополитика | Bruegel WP 32/2025, CRS Iran×2, REPowerEU progress |
| Краткосрочные цены | EIA STEO, IEF MOMR Comparative, IEA OMR free |
| Долгосрочная стратегия | OPEC AR + ASB, IEA Oil 2025, IEA Gas 2025, GIIGNL, ИНЭИ |
| Газовый рынок (отдельная половина задачи) | IEA Gas 2025, IEA GMR Q1-2026, GIIGNL, Газпром AR + Acc, Новатэк AR, REPowerEU |
| Запрос вне компетенции | (фильтр на этапе intent, корпус не задействован) |

Все 5 демо-сценариев из ТЗ покрываются этим набором.

### Что НЕ берём — сознательные исключения

1. **Глобальные мейджоры** (Saudi Aramco, Shell, ExxonMobil, BP, Chevron). Артём чётко обозначил: «отталкиваемся от полезности, а не от перегруженности». Глобальный взгляд покрыт через OPEC WOO/AR + IEA Oil/Gas + GIIGNL.
2. **Архив monthly-документов** глубже 1 номера. Лишние свежие архивы создают шум при retrieval, а свежие новости — задача web-search в runtime.
3. **Платные подписки** (Wood Mackenzie, Rystad Energy, S&P Platts/Argus, Refinitiv, Cedigaz). Open-access only.
4. **CSIS Iran HTML-articles**. Заменены на CRS PDF (Congressional Research Service) — институциональнее, цитируемее.

### Известные ограничения корпуса

| Ограничение | Митигация |
|---|---|
| **IEA OMR full** — paywall с 2020 ($11k/год) | Используем free version (~5 стр) — `iea_omr_2026-04_free.pdf` |
| **OPEC WOO** — требует одноразовой бесплатной регистрации на `publications.opec.org` | Артём скачал вручную (WOO 2025, 13.4 МБ); в манифесте отмечен `fetch_note`. OPEC AR 2024 + ASB 2024 остаются как комплементарные источники. |
| **OPEC MOMR** — Cloudflare challenge на `momr.opec.org/pdf-download/` | Заменён на **IEF Comparative Analysis April 2026** (содержит выжимки MOMR + IEA OMR + EIA STEO одновременно — даже информативнее) |
| **CSIS Iran** — публикуют только HTML, не PDF | Заменены на CRS reports |
| **Vygon Consulting** — WAF блочит curl | Не включён в авто-скачивание; опционален вручную через браузер с `vygon.consulting/pressroom/our-publications/` |
| **Газпром / Роснефть МСФО post-2022** | Был мой ошибочный тезис «не публикуют». **Роснефть публикует МСФО** — взяли `rosneft_ifrs_12m_2024.pdf`. **Газпром не публикует** — используем РСБУ-версию `gazprom_accounting_2024.pdf`. |
| **Российские сайты SSL timeout** с не-РФ IP (Газпром AR, Минэк, Татнефть в первой попытке) | `scripts/fetch_corpus_manual.sh` через VPN РФ. На момент PR Минэк/Татнефть/Газпром Acc собраны таким способом, Газпром AR помечен `pending_manual`. |

### Почему манифест в YAML, а не в коде

Манифест — **данные**, а не логика:
- Артефакт для review — Артём смотрит в одном файле что вошло в RAG
- Регенерируемость — `python scripts/fetch_corpus.py` пересобирает корпус с нуля где угодно (локально / Timeweb / у ревьюера ТЗ)
- Не требует деплоя — добавить новый документ = одна правка YAML + push
- Sha256 фиксируют идентичность файла → защита от подмены источника

Конкурент — JSON. Отвергнут: YAML лучше читается с длинными `purpose`-полями.

## Жизненный цикл

### Когда обновлять

| Триггер | Действие |
|---|---|
| Вышел новый MOMR/STEO/GMR/OMR | Заменить старый в манифесте, обновить sha256, повторно запустить `fetch_corpus.py` |
| Опубликован новый ИНЭИ Прогноз / IEA Oil / IEA Gas | Добавить новый, **сохранить** старый ещё на 1 год для сравнения |
| Новый годовой отчёт компании | Заменить старый |
| Изменилась стратегическая обстановка (новые санкции / новый этап Энергостратегии) | Добавить тематический документ в Блок 4 |

### Бюджет на обновления

Manual-обновление manifest + повторный `fetch_corpus.py` = ~10 мин.

## Связанные артефакты

- `docs/corpus.md` — **человекочитаемый каталог** корпуса с описаниями каждого документа (2-3 предложения), обоснованием достаточности через taxonomy вопросов и mapping на 5 демо-сценариев ТЗ
- `data/metadata/manifest.yml` — машиночитаемый список документов (используется `fetch_corpus.py`)
- `scripts/fetch_corpus.py` — основной идемпотентный fetcher
- `scripts/fetch_corpus_manual.sh` — для документов с региональным/WAF-блоком
- `data/corpus/` — целевая директория, **gitignored** (PDF-файлы тяжёлые, в репо лежат только манифест и скрипты)
- `docs/changelog/2026-05-05-corpus-bootstrap.md` — changelog PR

## Альтернативы рассмотренные

- **Сразу OpenAlex / arXiv API** — отвергнуто: нефтегаз не академическое поле, индустриальные отчёты ценнее.
- **Подписка на S&P Global Commodity Insights / Argus** — отвергнуто как платное и недоступное в РФ.
- **Wider scope (нефть + газ + уголь + ВИЭ + атом)** — отвергнуто, ТЗ только нефтегаз.
- **Только monthly archive (12 номеров MOMR + 12 STEO)** — отвергнуто как создающее retrieval-шум при дубликатах.

## Что НЕ делается в этом PR

- **RAG-пайплайн** (chunking, эмбеддинги BGE-M3, Chroma, retrieval, re-ranking) — отдельный ADR-0010 + PR `feature/rag-pipeline`.
- **Web-search tool** в runtime — отдельный PR `feature/web-search`.
- **Ценовые tools (Brent/WTI/Urals/HH/TTF)** — отдельный PR `feature/price-tools`.
- **Vygon Consulting автоматическая интеграция** — manual для v1, оценим необходимость в v1.x по результатам eval.
