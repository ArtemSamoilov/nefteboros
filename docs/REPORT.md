# Отчёт — AI-агент «Нефтегазовый аналитик»

> ТЗ §4.5. Архитектурный обзор — [docs/architecture.md](architecture.md), история решений — [docs/adr/](adr/).

## 1. Описание

**nefteboros** — агент в роли старшего аналитика нефтегазового рынка. Отвечает на профильные вопросы (Upstream/Midstream/Downstream, Brent/WTI/Urals/ESPO, ОПЕК+, санкции), строит сценарные прогнозы (нефть, газ, MOEX-equity), выполняет гибридный поиск по 25 отраслевым отчётам (RAG) и открытым источникам (веб) с маркировкой источников. Ouroboros — ядро цикла диспетчеризации инструментов, доменная логика — в подграфе LangGraph. Развёрнут на Timeweb VDS (Docker, веб-интерфейс на Streamlit).

## 2. Архитектура

Двухуровневая. **Внешний слой** — форк Ouroboros ([ADR-0001](adr/0001-fork-ouroboros.md)): диспетчер инструментов, маршрутизатор LLM, политика безопасности, веб-интерфейс; из исходного репозитория выпилены подсистемы самомодификации, магазин расширений, протокол A2A. **Внутренний слой** — подграф LangGraph `analyst_graph` ([ADR-0014](adr/0014-langgraph-subgraph.md)) внутри инструмента `analyst_query`: детерминированный оркестратор `classify_intent → route → {retrieve_rag | web_search | forecast_call} → synthesize → validate_citations`. Маршрутизация — регулярные выражения по 5 правилам разрешения неоднозначности, не «LLM сам решит». Полная схема — [docs/architecture.md](architecture.md).

| Слой | Технология |
|---|---|
| Ядро | Форк Ouroboros (Python 3.12), веб-интерфейс на Streamlit |
| Оркестрация | LangGraph (`analyst_graph`) |
| RAG | ChromaDB + BGE-M3 (мультиязычная), 802 чанка |
| Веб-поиск | Brave Search API + фильтр первого/второго уровня + определение языка |
| Прогноз | Процесс Орнштейна-Уленбека по режимам, для каждого сценария |
| Состав LLM | GigaChat-2-Max (основной), Hydra/kimi-k2p6, AItunnel (резервный) |
| Наблюдаемость | Langfuse Cloud + резервный JSON-трейс |

## 3. Технологии и обоснование

**Состав LLM — GigaChat + Kimi K2 (через Hydra) + резервный AItunnel** ([ADR-0007](adr/0007-llm-providers.md)). Разные модели на разные роли, протокол транспорта независим от поставщика, совместим с API OpenAI.

- **GigaChat-2-Max** — узел `llm_disambiguate` в `analyst_graph` ([ADR-0015](adr/0015-llm-disambiguate.md), `nefteboros/graphs/nodes/llm_disambiguate.py`): вызывается условным переходом, когда `classify_intent` на основе правил возвращает `matched_rule == "no_keyword_match"`. Структурированный JSON-вывод, перезаписывает `state.intent`. Модель Сбера применена там, где её сильные стороны в русскоязычной семантике дают наибольший выигрыш — на разрешении неоднозначности пользовательских запросов.
- **Kimi K2 (kimi-k2p6)** — основной обработчик для синтеза ответа и разметки чанков. **Модель Moonshot AI с открытыми весами** — при необходимости разворачивается в защищённом контуре Сбера (vLLM / sglang / llama.cpp), без зависимости от внешнего поставщика. В нашем развёртывании подключается через российский шлюз Hydra, совместимый с API OpenAI; смена на локальный сервер инференса — это правка `base_url` в окружении, без изменения кода. Контекст 256k и нативный вызов инструментов — вторичные плюсы.
- **AItunnel** — резервный провайдер (тот же протокол, совместимый с API OpenAI, те же модели с открытыми весами). Подключается автоматически через `OUROBOROS_MODEL_FALLBACK` при пустом ответе от основного провайдера.
- **OpenAI / Anthropic** отвергнуты — недоступны из РФ без VPN, неприменимо для агента под Сбер в промышленной эксплуатации.

**Прогноз — процесс Орнштейна-Уленбека с возвращением к среднему, не SARIMAX/ARIMA** ([ADR-0024-ou-regime-forecast](adr/0024-ou-regime-forecast.md)). Статистические модели (SARIMAX + GBR-ансамбль, изначально [ADR-0012](adr/0012-price-tools.md)/[ADR-0013](adr/0013-hybrid-forecasting.md)) дают расходящийся доверительный интервал (Var ∝ t): ширина ±30-40% на горизонте 12 месяцев — неприменимо на практике. Заменены на процесс Орнштейна-Уленбека для каждого сценария: `dS = θ(μ(t) - S)dt + σ dW`, Var → `σ²/(2θ)`, ограниченная сверху. Параметры μ/θ/σ откалиброваны через эластичность Килиана + банковский консенсус + историческую волатильность по режимам. Даёт практически применимый доверительный интервал в формулировке «при сценарии X целевой уровень $Y, скорость возврата Z, волатильность W» — как мыслит старший аналитик.

**RAG — Chroma + BGE-M3 + крупные чанки** ([ADR-0016](adr/0016-embed-retrieve.md), [ADR-0011](adr/0011-chunking-and-tagging.md)). Мультиязычные эмбеддинги (1024d) — корпус RU/EN ≈ 41/59. Чанки крупные (целевой размер 3000 токенов) — Kimi-2.6 работает с длинным контекстом, мелкие чанки дают шум. PDF→Markdown — Marker. Корпус собран от таксономии вопросов, не «качаем всё» ([docs/corpus.md](corpus.md)).

**LangGraph — детерминированный оркестратор.** Маршрутизация между прогнозом / RAG / веб-поиском — код с модульными тестами, не эвристический LLM-промпт. Системный промпт ([ADR-0019](adr/0019-system-prompt-analyst.md)) задаёт идентичность и форматы цитирования.

## 4. Ограничения

- **Верификация числовых значений не реализована.** Валидатор RAG проверяет факт цитирования, но не сверяет числа в ответе с числами в чанках — LLM может процитировать правильный чанк и написать неверное число. Двухуровневая верификация (регулярные выражения + LLM-верификатор) — отложено в план ([Track D4](roadmap-v2.1.md)).
- **Защита от инъекций в промпт — эшелонированная защита, не универсальное решение.** Содержимое из веба оборачивается в разделители `<external_content>`; системный промпт инструктирует игнорировать императивы внутри. На «послушных» моделях работает, полной гарантии нет.
- **Параметры прогноза экспертные, не MLE.** μ/θ/σ — банковский консенсус + Килиан + историческая волатильность по режимам, снапшот `as_of: 2026-05-08`. Сценарии `base`/`bull` на горизонте 12 месяцев имеют MAPE 30-50% в бэктесте на 5 годах — параметры под равновесие шока 2026, не универсальны по всем режимам (осознанное архитектурное решение).
- **Корпус заморожен на v2.0.0.** Поиск с учётом времени и индексация новых отчётов отвергнуты в плане развития. Свежесть — через веб-поиск. МСФО Газпрома недоступна после 2022, используем РСБУ.

## 5. Возможные улучшения

В порядке приоритета (адаптировано из [roadmap-v2.1.md](roadmap-v2.1.md)):

1. **Верификация числовых значений (Track D4).** Двухуровневая верификация (регулярные выражения + LLM-верификатор) для чисел в ответе — закрывает анти-галлюцинацию на числах, что для аналитика критичнее всего.
2. **Разрешение конфликтов.** Детекция и явное озвучивание расхождений между числами из RAG и веба на тех же сущностях — ключевая возможность для персоны старшего аналитика.
3. **Пользовательские сценарии для прогноза.** Сейчас три фиксированные предустановки (`bear`/`base`/`bull`). Программный интерфейс `ScenarioParams(flags=…)` уже реализован, нужно подключить определение во время выполнения для произвольных комбинаций драйверов.
4. **Калибровка для каждого снапшота в OU.** Калибровка по каждому режиму (PRE_2022 / WAR_SHOCK / CAP_NORMALIZATION) снизит MAPE на исторических периодах с текущих 30-50% на горизонте 12 месяцев.
5. **Самостоятельно развёрнутый Langfuse + сводка рассуждений в интерфейсе.** Бесплатный облачный план — для демо; для инфраструктуры Сбера нужно самостоятельное развёртывание (конфиденциальность). Параллельно — разворачиваемый блок «Источники и логика» под ответом.

## 6. Метрики качества
